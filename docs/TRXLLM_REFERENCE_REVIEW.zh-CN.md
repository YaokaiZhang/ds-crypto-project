# TrxLLM 文档评审：可借鉴方法、事实修正与 GraphSAGE 适配

评审日期：2026-10-05。对象：[信安大赛文档6.8版v7.pdf](../../TrxLLM/信安大赛文档6.8版v7.pdf)，共 73 个 PDF 页面。以下均使用 **PDF 页码**，对应正文印刷页码通常减 4。已提取全文，并对数据定义、图结构、模型公式、数据分布和结果表相关页面作渲染核对。附带 Vue 源码只用于核对当前本地交付范围。

结论：可以借鉴其“以目标地址/交易为中心、获取有限历史邻域、构建属性交互图、再做下游判别”的组织方式。不能直接采用其中若干区块链定义，也不能把闭源数据上的性能和系统截图视为我们 GraphSAGE 的可复现依据。当前方案不需要复制大模型架构才能成为一个完整系统。

## 1. 文档实际提出了什么

| 模块 | 文档描述 | 页码 | 对我们的价值 |
|---|---|---|---|
| 交易图构建 | 输入交易哈希或地址；获取历史交易并扩展邻域；账户作为节点，交易/调用作为边 | 14–22 | 可复用问题分解与目标中心局部图思路 |
| 属性处理 | EOA/合约属性、金额/gas/区块等交易信息、调用 trace；文本化后 BPE 分词/向量化 | 21–25 | 字段覆盖可作清单；数值/类别/时间应先按语义编码 |
| 图分析 | GIN 风格聚合，公式显式使用边嵌入；再进入 decoder Transformer | 26–30 | 说明边属性有研究价值；不等于现有 MeanSAGE |
| 预训练 | 对节点或边属性做掩码恢复，再微调下游任务 | 30–34 | 可作为有预算时的独立扩展，不是必需基础 |
| 下游任务 | 恶意交易识别、地址风险评估、合约函数名恢复 | 33–34、49–50 | 前两者与本项目部分相邻；函数名恢复与活动预测无直接必要关系 |
| 应用展示 | 查询、图展示、风险标签、实时页面 | 56–64 | 可参考界面信息组织；不能代替真实服务验收 |

文档使用默认约 30,000 个区块的时间邻近范围，并研究多跳扩展。对于我们的任务，应改成**明确截止时间之前的固定观察窗**。所谓“时间上最近”如果包含目标交易之后的数据，就不能用于提前检测；不同区块数也不保证相同实际天数。

其 GNN 公式中有 `ReLU(x_j + e_ji)`，说明边表示参与消息；我们的训练脚本当前只传入节点矩阵和连接索引。将同一份属性图保存下来，并不会让现有模型自动使用金额、方向或 trace。

## 2. 数据和实验结果能支撑到什么程度

文档报告预训练集合含 213,857 条交易，并使用 MetaTrust 合作数据；下游恶意交易集合声称 83,170 条，风险地址集合 5,000 个。我们拿到的是说明文档和前端，不是完整的闭源样本、拆分清单、训练代码、权重和运行配置。公开替代数据可支持我们自己的实验，但不能据此宣称复现该闭源结果。

### 2.1 文档内部需要澄清的地方

| 项目 | 阅读结果 | 影响 |
|---|---|---|
| 分类计数 | p39 列出 26,820、13,208、10,017、9,735、8,726、7,199、7,456，合计 **83,161**，与 83,170 差 9 | 需要原始 manifest 核对，不应照抄成已核验样本数 |

| 地址指标 | p50 表头为 accuracy、recall、micro-F1、balanced accuracy；正文指标描述不完全一致 | 不应跨表把精确率/准确率或 macro/micro 混用 |

## 3. 区块链描述哪些能用，哪些必须修正

可以采用“节点表示地址实体，边表示带时间与属性的交互”的高层描述，但底层事实应依据协议文档重写，不从竞赛文档逐句复制。

| 文档位置/表述 | 正确表述与本项目处理 |
|---|---|
| p16：access/cache 包含账户和私钥 | Access list 是地址与 storage keys；私钥不写入交易。删除错误描述。[EIP-2930](https://eips.ethereum.org/EIPS/eip-2930) |
| p17 表 2.2.2：Balance/Nonce 含义互换 | balance 是账户余额；nonce 是账户状态中的计数值。原表不能进入数据字典。[Ethereum accounts](https://ethereum.org/developers/docs/accounts/) |
| p16：Code/API、时间戳等当成一般交易自带字段 | 普通调用的 input 是 calldata；创建交易含 initcode。源码/ABI、函数解释往往来自额外来源；时间戳由所在区块关联。区分原生字段和派生注释。[Ethereum transactions](https://ethereum.org/developers/docs/transactions/) |
| p16：Type 按转账/部署解释；MaxFee 当最大 gas 量 | envelope type 与业务事件类型分列；gas limit、gas used、每 gas 价格及 fee cap 分列，注明单位。[Ethereum transactions](https://ethereum.org/developers/docs/transactions/) |
| p17：合约部署后代码与状态不可变 | 状态随执行变化；代理可改变执行逻辑。账户角色应结合区块状态与模式判断。EIP-7702 也允许 EOA 设置代码委托，不能把是否有 code 当永恒的二分身份。[EIP-7702](https://eips.ethereum.org/EIPS/eip-7702) |
| p18：蜜罐借用防御系统定义 | 本项目诈骗子类必须定义为合约诱捕或 token 卖出限制等具体机制。原始 HoneyBadger 研究关注诱骗攻击者利用假漏洞的合约陷阱，与现代卖出限制 token 不完全相同。[USENIX 原论文入口](https://www.usenix.org/conference/usenixsecurity19/presentation/ferreira) |
| p22：calltrace 被表述为能直接完整说明内部行为 | Geth callTracer 主要给调用帧，可配置日志；完整 opcode/storage 级执行信息是另一类 tracing。内部 Solidity 函数名也不自动恢复。[Geth built-in tracers](https://geth.ethereum.org/docs/developers/evm-tracing/built-in-tracers) |
| p22：hash/topics 可因“无意义”移除 | tx hash 不宜作为可记忆的监督特征，但必须保留溯源；event topics 对事件解码有意义。模型特征过滤与原始证据保留是两件事 |
| p33–34、50：十六进制函数标识按“无效函数名”处理 | 标准 ABI 调用前 4 字节是函数选择器。它不是天然无效数据，也不能唯一还原完整源码语义；需要 ABI/签名候选及上下文。[Solidity ABI](https://docs.soliditylang.org/en/latest/abi-spec.html) |

另一个直接影响现有项目的事实是：Uniswap v3 `Swap.sender` 是发起 swap 调用并接收 callback 的地址，可能是 router，并非必然的最终交易者。当前仓库将其作为 wallet 身份是一个明确的操作化定义，应保留角色限制及敏感性分析，而不称“真人交易网络”。[Uniswap v3 事件接口](https://github.com/Uniswap/v3-core/blob/main/contracts/interfaces/pool/IUniswapV3PoolEvents.sol)

### 3.1 建议用于我们报告的基础描述

> 本系统以 Ethereum 的地址实体与链上交互事件构建带时间的属性图。原始证据来自交易、交易回执及日志；按任务需要补充指定区块的账户/合约状态和调用 trace。地址可具有参与者、token、pool、部署者等多种角色；同一角色不代表同一自然人。外部交易、合约调用、token transfer 与 DEX swap 分别建模，并通过交易哈希、日志索引或调用路径关联。模型在每个目标实体的固定历史窗口内构建局部图，仅使用截止时刻已存在且符合来源可得性要求的信息。

这段描述可用于项目背景与数据章节，之后必须紧接所选数据源实际覆盖范围；不能让读者误以为本项目已经完整采集所有 trace、token 和协议。

## 4. 从 TrxLLM 到本项目 GraphSAGE 的映射

| TrxLLM 设计 | 我们的适配 | 适配等级 |
|---|---|---|
| 交易/地址为输入中心 | token 活动图以 token 为 root；诈骗图以待识别地址/合约为 root | 直接采用理念，分别构图 |
| 账户邻域扩展 | cutoff 前有预算的入/出账与调用邻域；保留采样规则 | 可复用基础框架，新增 adapter |
| 节点/边文本化 | 数值 log/scale、类别编码、时间 offset、缺失标记；文本字段单独决定是否使用 | 不照搬 tokenizer；先保留可审计字段 |
| 边属性 GIN + Transformer | 首期 native MeanSAGE；后续关系/方向感知 SAGE 独立实验 | 替换模型，不称同一架构 |
| 用两个端点 embedding 相加生成边表示 | 需要交易任务时使用有方向的 concat，加事件特征 | 相加是对称的，不能表达反向或同端点不同交易 |
| 掩码预训练 | 仅在训练期且排除 held-out 目标的事件上做可选预训练 | 需独立数据和泄漏合同 |
| 地址风险取最大交易分 | 训练地址级 root head；外部事件证据单列 | 避免把局部交易风险直接当地址恶意概率 |
| 多个下游任务 | 共享数据/图/训练框架，独立 head 与校准 | 首期不强制共享权重 |

若要证明边属性有效，最低实验组合是：相同 cohort 的表格统计、现有 MeanSAGE、显式方向/关系/边属性的 SAGE 变体。统一特征预算或增加对应邻域统计基线，避免只因输入信息变多而归因于架构。BPE/Transformer 的价值只有在这一层比较之后才值得进一步测试。

## 5. Honeypot 为什么不能只做“图分类即结论”

交易图能指出值得检查的买卖不对称和控制关系，却无法仅凭“没有成功卖单”区分无人卖出、未授权、滑点、路由错误、暂停交易、黑名单、动态税率等情况。一个账号可成功卖出也不能证明所有账号都可卖出。

建议分开保存三种输出：

1. 图模型筛查分：来自明确版本的 token 交易图，表示与训练案例的模式相似性。
2. 规则/状态证据：观察到的限制、权限、失败交易、来源和区块。
3. 模拟结果：固定 fork/block、调用者、资产余额、allowance、路由、数量、滑点和完整买卖序列下的结果；失败原因未知时标记不确定。

上述模拟应在隔离环境进行，不需要真实签名或资金交易。模拟只能说明所测试状态和条件，不保证未来状态或任意账户安全。GoPlus 等第三方接口可作为外部证据源，但应记录返回未知/缺失及查询时间，不作为唯一独立真值。[GoPlus 字段文档](https://docs.gopluslabs.io/reference/response-details)

## 6. 系统实现和复现层面的判断

文档 p64 报告图构建之外的模型延迟低于端到端延迟。这支持“分开测抓取、构图、推理”的工程原则，但不能把其秒数写成我们系统 SLA：模型、数据服务、缓存命中率、硬件和目标邻域均不同。

本地 `TrxLLM-Vue/src/views/TradeIdentification.vue` 将两个已知哈希转到专用结果页；`RealTimeData.vue` 用 5 秒定时器跳转。未据这些文件发现对应的真实分析调用。此结论仅针对提供的前端关键路径，不否认原项目可能另有未提供的后端。

对我们最划算的路线是：复用现有数据工程与小图 GraphSAGE，新增严格的 scam adapter 和独立监督任务，再实现无标签推理与统一证据 API。大模型训练、函数名恢复、跨链识别暂不进入主路径。

完整目标、数据源决策、共用组件、实验门槛与部署计划见 [系统需求与架构](SYSTEM_REQUIREMENTS_AND_ARCHITECTURE.zh-CN.md)。
